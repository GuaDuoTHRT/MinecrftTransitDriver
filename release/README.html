简介

MinecraftTransitDriver（MTR驾驶进阶） 是面向 MTR 驾驶与运营的扩展模组。

从 1.5.0 开始，本模组不再只是客户端模组，而是双端模组：

  • 客户端：提供左右开门键、仪表盘所有者选择界面；
  • 服务端：负责保存车站/线路所有者、记录玩家乘坐线路、出站扣费并把车费分给线路所有者团队。

它把「开哪一侧车门」的控制权交还给驾驶员：在驾驶列车时，用 左方向键 打开列车运行方向左侧车门，用 右方向键 打开右侧车门；两个按键都可以在 Minecraft 的「控制」设置中自由修改。使用左右开门键时，即使车站没有铺设站台方块，列车也会完整播放开门动画并完全打开对应侧车门。

同时，服务器管理员可以通过 MTR 仪表盘为车站和线路设置原版 scoreboard 团队作为所有者。乘客乘坐有主线路并在车站出站时，MTR 扣除的车费会按规则计入线路所有者团队成员的 mtr_balance 余额。

安装步骤

服务器

  1. 为 Minecraft 1.20.4 安装 Fabric Loader。
  2. 将 Fabric API、MTR 4.0.5+1.20.4 和本模组放入服务器的 mods 文件夹。
  3. 启动服务器。所有者和经济数据会保存在世界存档中。

客户端

  1. 为 Minecraft 1.20.4 安装 Fabric Loader。
  2. 将 Fabric API、MTR 4.0.5+1.20.4 和本模组放入 .minecraft/mods。
  3. 启动游戏。在「选项 → 控制 → 按键绑定」中可以看到 MTR驾驶进阶 分类。

模组文件：

text [MinecraftTransitDriver]1.20.4fabric_1.5.1.jar

请勿同时安装其他会修改 MTR 车门渲染逻辑的模组，否则可能出现车门动画冲突。

按键设置

  1. 打开 选项 → 控制 → 按键绑定。
  2. 找到分类 MTR驾驶进阶。
  3. 修改以下两项：
按键名称 默认按键 作用
开/关左侧车门 左方向键 打开或关闭列车运行方向左侧车门
开/关右侧车门 右方向键 打开或关闭列车运行方向右侧车门
  1. 点击「保存」或直接返回即可生效。

关于 MTR 默认开门键

MTR 原版的「列车开门/关门」默认键也是 左方向键。本模组会在检测到左右开门键被按下时，接管本次开门操作，避免同一次按键触发两次开关门。

如果你仍想使用 MTR 原版的「一键同时切换两侧车门」功能，请在按键设置中把 MTR 的「列车开门/关门」改到其他按键；单独按下该键时，本模组会恢复 MTR 原版的自动/平台判断行为。

关于 ATO 切换： MTR 4.0.5 将「列车开门/关门」键同时用于 ATO 切换（同一个按键）。为了避免按左方向键开门时误切换 ATO，本模组在使用左右开门键时会同时抑制这次按键对 MTR 原版车门和 ATO 的触发。若你需要切换 ATO，请把 MTR 的「列车开门/关门」改到另一个按键并单独按下该键。

驾驶员开门

前置条件

  • 你正在驾驶列车（坐在驾驶位并手持有效驾驶钥匙）。
  • 列车已经停稳（速度接近 0）。
  • 驾驶钥匙具有车门控制权限（普通驾驶钥匙通常具备；部分特殊钥匙可能没有）。

开门

  1. 将列车停稳在车站或任意需要开门的位置。
  2. 按 左方向键：打开列车运行方向左侧车门。
  3. 按 右方向键：打开列车运行方向右侧车门。
  4. 动作栏会显示当前状态，例如：

text 车门状态：左 开 / 右 关

关门

  • 再次按同一侧的方向键即可关闭该侧车门。
  • 如果两侧都关闭，列车会通过 MTR 的关门动画平滑关闭两侧车门。
  • 如果只关闭其中一侧、另一侧仍保持打开，被关闭的一侧会立即收起（不播放单独的关门动画），这是 MTR 共享车门动画值带来的限制。

无站台方块时开门

  • 使用左右开门键时，本模组会跳过「附近是否有站台方块」的检查。
  • 即使没有铺设 MTR 站台方块，车门也会完整播放开门动画并完全打开。
  • 该行为只作用于玩家正在驾驶的列车。完全无人的 ATO 列车仍遵循 MTR 原版自动门逻辑。
  • 站台屏蔽门（PSD/APG）存在时，手动开门侧仍会执行 MTR 原版检测，但开门请求会覆盖该检测的阻止结果；手动关闭侧会跳过该侧检测，以避免误开对应侧的屏蔽门。请提前确认现场安全。

门侧定义

本模组中的「左/右」指列车运行方向上的左/右，也就是从列车前部朝行进方向看时的左右两侧。

模组通过 MTR 列车模型中的标准 flipped（左右镜像）属性判断车门属于哪一侧。绝大多数 MTR 原版列车和遵循 MTR 资源规范的追加列车都能正确识别。

如果自定义列车模型没有遵循该规范，可能出现左右方向相反的情况。遇到这种情况请记录列车名称、模型来源和游戏日志，向模组作者反馈。

车站/线路所有者

设置位置

  1. 打开 MTR 仪表盘。
  2. 选择 车站 或 线路，进入对应的编辑界面（Edit Station / Edit Route）。
  3. 在编辑界面右上角会看到「所有者：…」按钮。
  4. 点击按钮，打开团队选择界面。
  5. 选择原版 scoreboard 团队，或选择「无所有者」清除所有者。
  6. 设置成功后，聊天栏会显示「已将车站/线路「名称」的所有者设置为团队「团队」」；清除时也会显示对应提示。

权限

  • 只有 OP（权限等级 2 及以上） 可以修改所有者。
  • 非 OP 玩家点击按钮会看到「只有管理员（OP）可以设置所有者」提示。
  • 服务器端会再次校验权限，客户端无法绕过。

数据保存

  • 所有者数据由服务器保存到世界存档，重启服务器后仍然有效。
  • 所有者变化会同步给安装了本模组的在线客户端。
  • 车站/线路被删除后，旧所有者记录不会参与分账；如团队被删除，分账会自动跳过。

团队要求

所有者使用 Minecraft 原版 scoreboard team，不是 MTR 的其它数据结构。

服务器上需要先创建团队，例如：

/team add THRT
/team modify THRT color aqua
/team join THRT PlayerName

然后在仪表盘中选择 THRT。

车费分成规则

触发条件

乘客必须满足：

  1. 乘坐过至少一条已设置所有者的线路；
  2. 在车站通过 MTR 出站闸机/出站处理器完成出站；
  3. MTR 实际从乘客的 mtr_balance 中扣除了车费。

满足后，车费会分给线路所有者团队，而不是出站站所有者团队。

分账方式

  • 采用 All one have 分成方式：线路所有者团队的每一名成员都会获得本次实际扣除的完整车费。
  • 团队成员包括在线玩家和离线玩家。
  • 离线成员会按玩家名写入 mtr_balance 记分项，不要求当时在线。
  • 如果团队没有成员、团队已删除、或没有乘坐有主线路，则不分账。

多条线路

如果一次行程乘坐了多条线路：

  • 只要其中至少一条有所有者，就会触发分账；
  • 以本次行程最后乘坐的有主线路的所有者团队为准；
  • 出站站的所有者不参与分账。

余额说明

  • 乘客余额仍由 MTR 原版 mtr_balance 记分项扣除；
  • 团队成员的 mtr_balance 会增加；
  • 分账完成后，在线团队成员会在聊天栏收到「团队获得余额」提示；乘客也会收到本次车费分配提示；
  • 由于采用「每个成员获得全额」的规则，本功能会创造新的 MTR 余额，请服务器管理员根据经济平衡自行评估。

示例

玩家 A 乘坐 THRT 所有的线路，出站车费为 80。
THRT 团队成员为 B、C、D（D 离线）。
结果：
  A 的 mtr_balance -80
  B 的 mtr_balance +80
  C 的 mtr_balance +80
  D 的 mtr_balance +80

版本号规则

本项目使用以下版本规则：

更新类型 版本变化 示例
小更新 +0.0.1 1.5.0 → 1.5.1
大更新 +0.1.0 1.5.0 → 1.6.0
Bug 修复 原版本后加 -hotfix 1.5.0 → 1.5.0-hotfix

小数位满 10 时向前进位：

1.5.9 + 0.0.1 = 1.6.0
1.9.9 + 0.0.1 = 2.0.0

历史版本：

  • 1.5.0：大更新，1.4.0beta → 1.5.0 正式版；
  • 1.5.1：小更新，新增所有者设置与团队分账的聊天栏提示。

多人游戏说明

  • 所有者数据由服务器保存并广播，客户端只负责显示和发送修改请求。
  • 服务器必须安装本模组；客户端未安装仍可加入服务器并正常乘坐/出站，分账在服务端完成。
  • 客户端安装本模组后，才能使用仪表盘所有者 UI 和左右开门键。
  • 左右门状态仍然只保存在驾驶端客户端；其他玩家看到的左右门侧别可能仍按 MTR 原版规则。
  • 如果服务器未安装本模组，客户端点击所有者按钮会提示「服务器未安装 MTR驾驶进阶」。

常见问题

Q：按方向键没有反应？

请依次确认：

  1. Minecraft 是 1.20.4，Fabric Loader 和 Fabric API 均已安装。
  2. MTR 是 4.0.5+1.20.4，不是 1.20.1 或其他版本。
  3. 你正在驾驶列车，而不是以乘客身份乘坐。
  4. 列车已经停稳。
  5. 手持的驾驶钥匙具有开门权限。
  6. 「选项 → 控制」中没有把左右开门键绑定到冲突按键。

Q：仪表盘里没有「所有者」按钮？

请确认：

  1. 客户端和服务器都安装了 1.5.1 版本的模组；
  2. 你打开的是车站或线路的编辑界面；
  3. 按钮位于编辑界面右上角；
  4. 如果服务器未安装本模组，按钮点击后会提示服务器缺少模组。

Q：为什么我不能设置所有者？

只有 OP（权限等级 2 及以上） 可以设置。请让服务器管理员使用 /op <玩家> 授权。

Q：为什么出站后没有分账？

请检查：

  1. 服务器安装了本模组；
  2. 乘客确实乘坐过已设置所有者的线路；
  3. 乘客通过 MTR 出站闸机/出站处理器出站，并实际扣除了车费；
  4. 线路所有者团队仍然存在；
  5. 团队中至少有一名成员。

注意：分账对象是线路所有者团队，不是出站站所有者团队。

Q：为什么多个团队成员都拿到了全额？

这是 E方案B 的设定：每名团队成员都获得本次实际扣除的完整车费。该规则会产生额外余额，请管理员根据服务器经济情况决定是否使用。

Q：离线团队成员会入账吗？

会。模组会按玩家名写入 mtr_balance 记分项，不要求成员在线。

Q：为什么左方向键同时是 MTR 的开门键？

MTR 原版的开门键默认就是左方向键。本模组已处理该冲突：按下左方向键时优先执行「打开/关闭左侧车门」，并抑制 MTR 原版同一次按键的重复切换。你也可以在控制设置中把两者改成不同按键。

Q：没有站台方块，为什么自动停站时车门还是不显示打开？

本版本的「无站台也开门」通过左右开门键触发。请在列车停稳后按左/右方向键开门。完全无人的 ATO 列车仍使用 MTR 原版逻辑。

Q：关门时为什么有一侧是瞬间收起？

MTR 所有车门共享同一个开门动画值。当另一侧仍然打开时，本模组只能把当前侧的车门动画归零，因此表现为瞬间收起。两侧都关闭时，会使用 MTR 的正常关门动画。

Q：左右方向反了怎么办？

这通常说明自定义列车模型的 flipped 约定与 MTR 标准不一致。请反馈列车模型名称和来源；在修复前可以暂时通过交换左右开门键来适应。

Q：会影响存档吗？

会新增一份所有者数据，保存在世界存档中；不会修改 MTR 的原有数据文件。删除模组后，存档仍可正常使用，只是所有者与经济功能不再生效。

从源码构建

项目使用 Fabric Loom 1.10.5 与 Gradle 8.12。

# Windows
gradlew.bat build

# macOS / Linux
./gradlew build

构建产物位于：

build/libs/[MinecraftTransitDriver]1.20.4fabric_1.5.1.jar

项目依赖（MTR、Fabric API、Fabric Loader）不会被打包进最终模组。发布时请让玩家自行安装对应依赖；libs/ 中的 MTR jar 用于本地编译。
